## 1. 链上社区积分(V2)

### 1.1 愿景

社区成员未来会接入链上账户(SIWE 钱包登录)。成员的社区贡献以**链上积分**记录:

**赚取**:签到参与、host 活动、志愿者服务、speaker 分享、社区贡献(管理员认定)等。
**消耗/兑换**:收费场地使用权、社区内咖啡、住宿等服务。
**原则**:

- **链上为权威**:积分余额与流水以链上(或 CAS 同步链上的账本)为准;业务系统(CommunityOS 等)数据库只是**镜像存储**,用于展示与快速查询。
- 积分不与法币强绑定(冷启动);兑换服务由社区运营规则决定。

### 1.2 对当前系统的预留(已体现在设计中)

| 预留点 | 当前位置 | V2 动作 |
| --- | --- | --- |
| 积分价字段 | VenueRule.points_per_hour(默认 0) | 规则配置非零即启用扣减 |
| 扣减代码路径 | Booking 结算走 CAS points/adjust(feature flag 关闭) | 打开 flag |
| 镜像表 | PointsMirror / PointsLedgerLocal(只读) | 对接 CAS/链上同步 |
| 赚取入口 | 无(一期不实现) | host_reward / attend_reward / volunteer / speaker 等 reason 在 CAS 账本落地 |
| 钱包登录 | 无 | CAS 增加 SIWE(Social Layer 已有成熟实现可参考:nonce + EIP-4361 消息签名,15 分钟 nonce TTL,防重放) |

### 1.3 数据流(V2 目标态)

    成员行为(签到/host/志愿者/speaker)
        |
        v
    CAS 账本(权威)  <----> 链上合约(权威/可验证)
        |
        v 同步
    业务系统镜像(展示)  -->  兑换服务(场地/咖啡/住宿)经 CAS 扣减

## 2. NFT 签到签发(V2)

### 2.1 愿景

活动签到未来接入**外部 NFT 系统**,自动签发参与凭证 NFT:

- **主持人持有二维码,扫一次变一次**(轮换二维码,防截图转发);
- 参与者现场扫描获得**一次性领取网址**(带签名、一次性消费);
- **数字上限**:每个活动的 NFT 签发数量有上限(如仅前 50 名到场者)。

### 2.2 流程(V2 目标态)

    主持人打开活动管理页 -> 展示当前轮换二维码(每被扫一次立即失效并生成新码)
      -> 参与者扫码 -> 打开一次性领取网址(活动 URL + CAS 签名)
      -> 业务系统调 CAS /checkin/claim 校验(一次性、未过期、未超上限)
      -> CAS 登记领取并通知外部 NFT 系统签发 -> 参与者钱包收到 NFT
      -> 领取计数 +1,达上限后后续扫码返回"已领完"

### 2.3 一期已实现的部分(不依赖 NFT)

- CheckinToken 实体与 claim_url 机制(CAS 签发,见 06 3.5);
- 轮换二维码接口(/events/{id}/check-in/rotate);
- 一次性消费与 409 语义;checkin_claim_cap 人数上限字段。

### 2.4 V2 待办

- CAS 对接外部 NFT 系统(合约或第三方平台);claim 成功后异步签发,失败重试与人工补发。
- 参与者钱包地址收集(签到页引导连接钱包,经 CAS SIWE 绑定)。
- NFT 元数据规范(活动名、时间、场地、角色:参与者/host/speaker/志愿者)。
- 徽章与 Social Layer 凭证的互操作(参与凭证可携带,见 01 调研第 2 节"Memory and After-life")。

## 3. 与其他系统的关系

- **CAS**:积分与 NFT claim 的权威层(06 文档)。
- **Social Layer**:身份/徽章体系可互补;NFT 凭证可与其徽章互认(远期)。
- **4seasbot**:签到结果、积分到账可经 outbox 推送通知(一期机制已支持)。
