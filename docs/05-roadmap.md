## 2. M0:地基(第 1-3 周)

**目标**:最小可运营——账户通、场地上线、活动能发。

范围:

- 技术底座:模块化单体、PostgreSQL、对象存储、事务邮件、任务队列、审计日志框架。
- **CAS 对接**:注册/验证/登录跳转与回调、/me 同步、用户镜像表(cas_user_id、cas_verified)。
- Place:建筑/楼层/场地 CRUD;基础信息(面积/设备/容量/开放时间);状态管理。
- Event:draft → preview → published → ended 状态机;快速创建(标题/时间/场地)与完整创建;可见性。
- Notify:邮件通知(发布、提醒);通知 outbox 数据模型(供 M1 的 4seasbot 拉取)。
- 运营后台雏形:场地、成员镜像、活动列表。

验收标准:

- 新用户经 CAS 完成注册验证并登录本系统。
- 管理员 10 分钟完成一栋楼的建筑-楼层-场地录入。
- 成员创建活动并发布,公开页可访问,邮件通知到达。

---

## 3. M1:运营闭环(第 4-7 周)

**目标**:场地可订、通知可达 4seasbot、签到可跑。

范围:

- Booking:独立预订 + 随活动预订;冲突检测(含缓冲);审批(auto / venue_manager / admin);取消政策;积分字段默认 0(接口预留)。
- 场地规则:活动类型白名单、提前窗口、时长上限、禁止行为条款(预订时确认)。
- **4seasbot 出站 feed**:/v1/integrations/bot/events 与 /notifications;4seas-bot 仓库提交 CommunityOS 数据源适配器 PR(拉取式,fallback 链最上游)。
- Check-in:轮换二维码 + 一次性领取网址(经 CAS 签发)+ 人数上限。
- Schedule:日/周/列表视图;iCal 订阅输出。
- 通知矩阵落地:邮件 + 4seasbot 拉取投递。

验收标准:

- 成员独立预订场地,审批(自动/人工)全流程通;冲突被拒。
- 4seasbot 拉取本系统活动并推送 digest;提醒消息到达绑定用户。
- 一场活动从创建到发布到通知无人工搬运;签到扫码 → 一次性领取网址消费成功。

---

## 4. M2:分发与 Agent(第 8-11 周)

**目标**:对外分发自动化,Agent 可查询与创建。

范围:

- **Luma 单向发布**:字段映射、封面上传、限流退避、两步取消、对账。
- **Social Layer 单向发布**:服务账号 JWT + api.sola.day/api/v1(POST /events 等);契约容错;computer-use 兜底预案。
- **Agent API**:REST v1(draft+confirm)+ MCP server;key 管理、scope、审计界面。
- 报名管理:嘉宾名单、候补。
- 数据导出(CSV/JSON)。

验收标准:

- 活动发布后 1 分钟内 Luma/sola.day 可见;每日对账无差异告警。
- 外部 Agent 经 MCP 完成"查场地 → 草稿创建 → 人类确认 → 发布"全流程,审计可回放。

## 5. V2:远期(规划,见 07)

- **链上积分**:CAS + 链上权威;签到/host/志愿者/speaker 赚取;兑换场地/咖啡/住宿;SIWE 钱包登录。
- **NFT 签到**:外部 NFT 系统对接;轮换二维码 + 一次性领取 + 数字上限全自动签发。
- **Telegram Mini App**:完整创建/预订表单,经 4seasbot 入口唤起。
- Luma webhook 回写(报名数据回流)、徽章/成就、活动模板、Program 运营、多语言。

## 7. 风险与缓解

| 风险 | 影响 | 概率 | 缓解 |
| --- | --- | --- | --- |
| CAS 交付延迟 | M0 登录受阻 | 中 | 本系统先以 CAS 接口契约为 mock 开发;CAS 基础版本并行开发(已启动) |
| Social Layer API 无文档、契约变更 | 同步失败 | 中 | 字段容错、单条失败跳过;computer-use 兜底;对账告警 |
| Luma Plus 未订阅/失效 | 同步降级 | 中 | 功能开关;仅站内发布模式 |
| 邮件到达率低 | 注册转化崩坏 | 中 | CAS 侧独立域名 + SPF/DKIM/DMARC;监控退信 |
| 社区迁移阻力(习惯微信/sola.day) | 采用率低 | 高 | 种子数据导入;首批 2-3 个活动试点;sola.day 保留只读 |
| 4seasbot 改动影响现有生产 | 社区播报中断 | 中 | 适配器以新数据源形式加入,默认关闭,灰度后启用;保留原 Sola 源为 fallback |
| 积分规则争议(V2) | 社区矛盾 | 中 | 规则透明 + 版本化 + 申诉通道;一期积分不启用 |
| Agent 误操作 | 数据错乱 | 中 | draft+confirm、scope 最小化、限流、审计、一键吊销 |

---

## 8. 范围裁剪原则(防蔓延)

1. 每阶段只做一个"不可逆"决策:M0 = 数据模型冻结;M1 = 规则引擎冻结;M2 = 同步契约冻结。
2. 新需求进下一阶段池,当期不加。
3. 账户/积分/签到/NFT 一律不自建,走 CAS。
4. 付费收款不自建(Luma Stripe / Telegram Payments)。
5. Telegram Mini App、链上积分、NFT 一律 V2。
